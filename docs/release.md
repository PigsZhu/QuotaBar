# 发布说明

## 准备首次公开源码

源码导出工具需要 Python 3.9 或更新版本。在原开发目录执行：

```bash
python3 script/prepare_source.py
```

输出 `dist/QuotaBar-<版本号>-source/`。这是按文件清单复制的源码副本，包含代码、测试、构建脚本、必要图标和公开说明，排除以下内容：

- 本地 Git 历史、编辑器及 Codex 配置。
- 机器迁移记录、设计草稿、动画试验工具及参数。
- 账号文件、环境变量文件、密钥、日志和构建缓存。
- 收费字体文件、安装包及历史备份。

脚本不覆盖已存在的目标目录。如需再次导出，可指定新的空目录：

```bash
python3 script/prepare_source.py --output dist/QuotaBar-source-review
```

**首次公开仓库应从该源码副本建立新的 Git 历史。** 旧开发历史保留供本地回退，其中可能仍有旧路径和个人提交身份；只删除当前文件不会清除历史内容。新仓库提交时使用拟公开的作者信息，不要直接推送旧开发仓库。

导出脚本中的检查只能发现部分常见凭据格式及个人目录路径，不能替代人工检查。发布前检查导出内容和提交信息。

## 发布前验证

1. 在干净源码副本运行 `swift test`。
2. 运行 `./script/build_and_run.sh --package-universal`。
3. 检查压缩包只有 `QuotaBar.app`，且不含 `.otf`、`.ttf`、`.woff` 或 `.woff2` 文件。
4. 检查两种架构、签名、首次启动、额度刷新、开合、关于窗口及退出。
5. 如面向普通用户正式发布，完成 Developer ID 签名及苹果公证；未完成时明确标为测试版。
6. Intel 及较早 macOS 版本未验证前，不将编译成功描述为实机验证通过。

## GitHub 发布内容

源码仓库只提交导出的源码。安装包通过与 `VERSION` 一致的 tag 和 Release 提供，不提交到源码仓库。首次版本为 `v0.1.0`，发布内容可根据 [更新记录](../CHANGELOG.md) 编写。

发布说明应注明：最低系统版本、需要本机登录 Codex、公开版本使用系统字体、签名和公证状态，以及尚未覆盖的实机测试范围。

不要上传本地带商业字体的开发版 `.app`。若将来希望恢复字体嵌入，须先取得适用于该应用及分发方式的授权，再调整发布配置。
